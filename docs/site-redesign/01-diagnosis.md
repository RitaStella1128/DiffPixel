# Phase 1 — 診断と作業モード決定

## 作業モード: **モード B(根本的再設計)**

### 根拠

- 既存サービスサイトが `docs/` に存在する(LP / マニュアル / プライバシーの 3 ページ + リダイレクタ、EN/JA 完備)。
- 情報構造は再利用可能: ページ構成(ヒーロー → ワークフロー → 機能 → プライバシー → CTA → フッター)は本指示書 3-1 の最小集合をほぼ満たし、文言は README / ストア文言と整合した検証可能な内容で、誇大表現・プレースホルダを含まない。
- したがって「情報は継承し、視覚・体験層を刷新(完成)する」モード B が適合する。全破棄・新規構築(モード A)は情報資産を損なうだけで利得がない。

## 既存実装の問題点(観点別)

### タイポグラフィ階層
- 階層自体は 4 段(display h1 / h2 / h3 / body)で規律があるが、**行間・字間・約物処理が個別ページ CSS に散在**し、タイポグラフィのトークン化(CSS 変数化)が不完全(サイズは clamp 直書き)。
- 見出しは静的に表示されるのみで、主視覚要素としての「登場」の演出(分割スタッガー)がない。

### 余白システム
- セクション padding は clamp ベースで概ね一貫しているが、値がマジックナンバーでトークン化されていない。

### モーション有無
- **スムーズスクロールが CSS `scroll-behavior: smooth` のみ**(慣性・イージング制御なし)。Lenis 未導入。
- スクロール連動は IntersectionObserver によるクラス付与 1 種(snap-in)のみ。**テキスト分割アニメーションなし**、スタッガー入場なし、GSAP/ScrollTrigger も CSS scroll-driven animations も未使用。
- マイクロインタラクションが**色変化 1 種のみ**(下線描画・磁気追従等なし)。`:hover` と `:focus-visible` の演出も非対称(focus はグローバル outline のみ)。

### テンプレート的既視感
- 「ダーク背景 + モノスペース見出しラベル + 直角罫線」は開発者ツール LP の定番構文であり、drift-title 等の独自部品はあるものの、**面がフラット単色の連続**(グレイン・グラデーション等の質感層が未実装)で、静止状態では既視感が残る。

### コントラスト比
- 主要組合せは AA を満たす(実測は Phase 4 で全数確認): `--muted #a7afc4` / `#080910` ≈ 8.9:1、`--quiet #737d98` / `#080910` ≈ 4.8:1、cyan ボタン `#031319` on `#00d7ff` ≈ 10:1。
- ただし `--quiet` は 9〜10px の極小テキストに使われており、4.8:1 は AA 通過とはいえ余裕が薄い(据置きだが Phase 4 で全数実測する)。

### モバイル体験
- **700px 未満でヘッダー CTA が `display: none`**。ページ中腹から CTA へ到達するには hero か closing まで大きくスクロールする必要があり、指示書 3-1-3「任意のスクロール位置から 2 操作以内」を満たさない。
- レイアウト崩れ・横スクロールは前回 QA(`design-qa.md`)で 320/390px 検証済み。

### LCP / CLS 要因
- LCP: hero 画像(webp 30KB, preload + fetchpriority=high)、フォント preload 済で良好。外部リクエストは Google Fonts(Noto Sans JP)のみ。
- CLS: 全画像に width/height 指定済。フォント swap 時のリフローは残る(metric-matched fallback なし、前回 QA で既知のトレードオフとして記録済)。
- リスク: 新規モーション導入時に JS で初期 opacity:0 を敷くと、JS 無効・reduced-motion 環境で不可視残留が起きうる → **可視をデフォルトとし、モーション有効時のみ JS が初期状態を作る**方針を Phase 3 で徹底する。
