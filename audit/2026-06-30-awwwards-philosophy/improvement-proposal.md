# DiffPixel 改善提案

監査結果を、中心思想「1pxのズレが、見える。」の純度を上げる順に並べる。新しい装飾を足すのではなく、言語、状態変化、操作、余白の精度を製品の精度と一致させる。

> 実装状況: 2026-06-30にPhase 1〜3を反映し、320px〜1440pxの英日表示で再検証済み。詳細はプロジェクトルートの`design-qa.md`を参照。

## Phase 1 — 言語と操作の精度を直す

### 0. 英語ページのモバイル横幅を最優先で修正する

対象:

- 英語トップのPrivacyマーク
- 英語ManualのHero、製品画像、章ナビ
- 英語Privacy PolicyのHeroと本文章

実装案:

- `.editorial-hero > *`、`.hero-visual`、`.chapter-body`へ`min-width: 0`を指定する。
- 640px以下の`.chapter`を`grid-template-columns: minmax(0, 1fr)`にする。
- 見出しと本文へ`max-width: 100%`、必要箇所へ`overflow-wrap: break-word`を付与する。
- Hero画像とcaptionがグリッドの最小内容幅を押し広げないよう、`width: 100%`と`min-width: 0`を確認する。
- トップの`.privacy-mark`はモバイルでフォントサイズとpaddingを下げ、`LOCAL`の5文字が内側幅へ収まるようにする。
- `overflow-x: hidden`で症状を隠さず、`scrollWidth === clientWidth`を完了条件にする。

完了条件:

- 320px / 390px / 768pxで英語3ページの横スクロールと内容欠けがない。
- ManualとPrivacy Policyの見出し、本文、画像、章ナビを最後まで読める。
- `LOCAL`の左右が完全に表示される。

### 1. 日本語見出しを言語別に再編集する

対象:

- `一つのパネルに、すべての確認。`
- `あなたの画像は、あなたの端末に。`
- モバイルの章見出し全般

実装案:

- 日本語のモバイル`h2`を英語と別スケールにし、現在の`16vw`から約`12.5〜13.5vw`へ下げる。
- `line-break: strict`、`word-break: normal`、`text-wrap: balance`を日本語見出しへ適用する。
- 意味単位を確実に守る必要がある見出しは、言語別HTMLで明示改行する。
- 1文字だけ次行へ送られる状態と、単語の途中で分かれる状態を390px / 320pxで確認する。

完了条件:

- 「パネ / ル」「あな / た」のような分割がない。
- 390pxで見出しが4行以内に収まり、本文または画像が同一画面内に少し見える。

### 2. Reduced Motionを静的な理解へ切り替える

実装案:

- JavaScriptで`matchMedia('(prefers-reduced-motion: reduce)')`を確認し、該当時はWorkflow用IntersectionObserverを生成しない。
- CSSのReduced Motion内で、デスクトップでも固定ステージを非表示にし、モバイルと同じ`コピー + 対応画像`の縦積みにする。
- transition時間を短くするだけでなく、スクロールに応じて画像が切り替わる仕組み自体を停止する。

完了条件:

- Reduced Motionでは3状態が静的な文書順で理解できる。
- スクロール位置に応じた画像の差し替えが発生しない。

### 3. 比較スライダーのキーボード処理を統一する

実装案:

- 左右矢印をどちらも明示処理し、通常は1、Shift併用は10ずつ増減する。
- 明示処理時は`preventDefault()`してネイティブ処理との二重加算を避ける。
- `aria-valuetext`を英語では`50 percent`、日本語では`50パーセント`へ切り替える。
- 0 / 100の境界、Home / Endの動作も確認する。

完了条件:

- 左右矢印、Shift + 左右矢印、ポインター、タッチで表示位置とアクセシブル値が一致する。

## Phase 2 — 情報の出会い方を整える

### 4. Capabilitiesを一つの画面状態へまとめる

実装案:

- デスクトップの上下paddingと日本語見出しを少し縮め、製品画面と8項目の先頭行が900px高の画面へ同居するよう調整する。
- 固定ヘッダー下で見出し上端だけが残る中間状態を避けるため、セクションのscroll marginと内部余白を再調整する。
- 8項目は小ささを維持しながら、製品画面との距離を短くする。

完了条件:

- 1440 × 900で「見出し / 製品画面 / 機能メタ情報」の関係が一度に理解できる。

### 5. 小さい操作対象を広げる

実装案:

- 言語ボタンを最低44 × 44pxへする。
- PrivacyとFooterリンクに透明paddingを追加し、見た目の文字サイズは維持しつつ操作領域を最低32〜44pxへ広げる。
- デスクトップのヘッダーナビにも上下paddingを与える。
- `:focus-visible`の3px cyan outlineは維持する。

完了条件:

- 主要なリンク・ボタンがタッチで選びやすく、隣接対象と誤操作しにくい。

### 6. モバイルの終端を短くする

実装案:

- `.closing`を68svhから約56〜60svhへ、`.site-footer`を46svhから約36〜40svhへ縮める。
- CTA後の余白を削りすぎず、次のワードマークが画面下端から少し見える状態を作る。
- Footerワードマークは左右を切らず、現在の下端10%クリップを維持する。

完了条件:

- CTA画面から1回程度のスクロールでFooterリンクへ到達できる。

## Phase 3 — 配信品質を揃える

### 7. フォント配信を整理する

実装案:

- Noto Sans JPの実使用ウェイトを洗い出し、400 / 500 / 700 / 800程度へ削減する。
- 可能なら可変フォントをセルフホストし、`font-display: swap`とメトリクス調整済みフォールバックを指定する。
- 英語のSyneは巨大見出しとワードマークへ限定し、UIと本文は読みやすい書体へ固定する。

完了条件:

- フォント未取得時もレイアウト変化が小さく、日本語内の数字・英字が浮かない。

## 推奨実装順

1. 英語ページのモバイル横幅
2. 日本語見出し
3. Reduced Motion
4. スライダーのキー操作と読み上げ
5. 操作対象サイズ
6. Capabilitiesの画面構成
7. モバイル終端余白
8. フォント配信

Phase 1は体験の正しさ、Phase 2は理解速度、Phase 3は配信安定性を改善する。見た目を刷新せず、現在の中心思想とアートディレクションを保ったまま実施できる。
